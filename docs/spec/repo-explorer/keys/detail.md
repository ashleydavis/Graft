# Keyboard shortcuts for the repo explorer

## Overview

The repo explorer is the repo explorer page's columns: the repo details pane (see [repo-details](../repo-details/detail.md)), the commit pane or the branch pane, the commit details pane and the file pane or the "Commit details" pane in its place (see [columns](../columns/detail.md)), or the changes pane and its file pane (see [changes](../changes/detail.md)), or the tag pane. Its keys work as in the column view of macOS Finder: Left and Right move between the panes, Up and Down move between the items in a pane, Page Up and Page Down move a page at a time, Home and End jump to the first and last item, Enter opens and Escape goes back. Ctrl+C (Cmd+C on macOS) copies the selected item. Ctrl+1 (Cmd+1 on macOS) returns to the repo explorer from any page.

## Behaviour

- One of the open panes is the active pane, which the keys act on. Its border is in the theme's primary colour. The repo details pane is active when the repo explorer page opens.
- Each pane's items, the Commits and Changes links, the branches and the tags in the repo details pane, the commits in the commit pane, the "Commit details" row and the changed files in the commit details pane and the rows of the changes pane, are MaterialUI `ListItemButton`s. The selected item has `selected` set, so it shows MaterialUI's own selection styling. No item is selected when the repo explorer page opens or a pane opens. The title of the commit whose details are open is bold.
- Up and Down move the selection to the item above or below in the active pane. At the first or last item the selection stays where it is. With no item selected, either key selects the first item. In the repo details pane they move through the Commits and Changes links, then the branches. In the changes pane they move through the Unstaged rows, then the Staged rows. The branch pane lists its commits as the commit pane does, and the keys move through it and open its commits in the same way. In the file pane, which shows a diff, Up and Down leave the selection as it is. In the commit pane they move through every commit read so far, across the pages, and the list scrolls by the least amount that brings the selected commit's row into view. Moving the selection near the last commit read scrolls the list there, which reads the next page, so Down reaches the repo's first commit.
- Home and End move the selection to the first and last item in the active pane, as far as Up or Down pressed again and again would. With no item selected, Home selects the first item and End the last. In the changes pane Home selects the first Unstaged row and End the last Staged row. In the file pane Home and End leave the selection as it is. In the commit pane End selects the last commit read so far and the list scrolls to it, which reads the next page, so the next End goes further. The newly selected row scrolls into view by the least amount, as it does for Up and Down. Wherever Up and Down open the newly selected item, Home and End do too: in the commit pane while a commit's details are open, in the commit details pane while no file pane is open and in a commit's changed files while a file's diff is open.
- Page Up and Page Down move the selection in the active pane up or down by the number of whole rows that fit in the scrolling area of the list it moves through, as the pane is drawn when the key is pressed, so a page follows the window's size and zoom. Each does what Up and Down do there, a page at a time: at the first or last item the selection stops there, with no item selected either key selects the first item and in the changes pane they move through the Unstaged rows, then the Staged rows. The newly selected row scrolls into view by the least amount. In the commit pane, moving the selection near the last commit read reads the next page, as Down does. In the changes pane the page is the rows that fit in the list that holds the selected row. In the repo details pane Page Down moves to the last link and Page Up to the first. In the file pane the keys leave the selection as it is.
- The selected row of the changes pane is always in view. When it becomes selected, its list scrolls by the least amount that shows its whole row.
- The selected row in the commit details pane, a file or the "Commit details" row, is always in view. When it becomes selected, from the first file as the list opens or as Up and Down move through a list longer than the pane, the pane scrolls by the least amount that shows its whole row.
- While a commit's details are open, Up, Down, Page Up and Page Down in the commit pane also open the newly selected commit, so the commit details pane shows it at once. The commit pane stays active and any file pane closes. At the first or last commit the details stay as they are.
- With the commit details pane active and no file pane open, as after Enter on a commit, a click in the commit details pane or Right, Up and Down open the commit above or below and Page Up and Page Down open the commit a page away, as they do in the commit pane, so the commit details pane shows it at once. The commit details pane stays active. At the first or last commit the details stay as they are.
- The commit details pane's rows run from the "Commit details" row at the top through the changed files: Up from the first changed file selects the "Commit details" row and Down from it selects the first file.
- While a file's diff or the "Commit details" pane is open, Up, Down, Page Up and Page Down in the commit details pane also open the newly selected row at once, without Enter, in the same place: a file's diff in the file pane, or the "Commit details" pane for the "Commit details" row. The commit details pane stays active.
- Right makes the pane to the right active, when there is one. Left makes the pane to the left active, when there is one.
- Enter on the selected Commits link opens the commit pane and makes it active. Enter on a selected commit opens its details in the commit details pane with its file pane closed and makes the commit details pane active, also when Up or Down already opened them. Enter on a selected file, in the commit details pane or the changes pane, opens its diff in the file pane and makes the file pane active. Enter on the selected "Commit details" row opens the "Commit details" pane and makes it active. Enter on the selected Changes link opens the changes pane and makes it active. Enter on a selected branch opens its branch pane and makes it active. Enter on a selected tag opens the tag pane in place of any other pane and makes it active. With no item selected, Enter leaves the panes as they are.
- M maximises the active pane, so it fills the repo explorer and the other panes are hidden, and M again puts every pane back (see [columns](../columns/detail.md)). It works the same with Caps Lock on. M held with Shift, Ctrl, Alt or Cmd does nothing, and M typed in a text box, such as the commit message box, types the letter.
- While a pane is maximised it stays the active pane: Up, Down and Enter work in it as before, and Left and Right leave it active. Escape closes the maximised pane and every pane to its right, puts the other panes back and makes the pane to its left active. With the repo details pane maximised, which always stays open, Escape puts the other panes back. Enter that opens the next pane and makes it active puts every pane back.
- C collapses the active pane into its strip (see [columns](../columns/detail.md)), and C while a collapsed pane is active restores it. The active pane stays the same, and a collapsed pane's strip has the active pane's border while it is active. Left and Right move through a collapsed pane as through any other. The keys act on a collapsed pane as on an open one: Up and Down move its selection, which the user sees in the panes to its right, such as the commit details pane following the commit pane's selection, and Enter opens its selected item in the pane to its right and makes that pane active. C is left to a text box that has the focus, and is ignored while Shift, Ctrl, Alt or Cmd is held. Clicking a pane's collapse button or a strip's restore button makes that pane active. C does nothing while a pane is maximised.
- Escape closes the rightmost pane and makes the pane to its left active. Closing the "Commit details" pane makes the commit details pane active and keeps the "Commit details" row selected. Closing the commit details pane keeps the commit selected. Closing the commit pane keeps the Commits link selected, closing the branch pane keeps its branch selected and closing the changes pane keeps the Changes link selected and closing the tag pane keeps the tag selected. With only the repo details pane open, Escape leaves it open and active.
- Clicking the Commits link selects it, opens the commit pane and makes the repo details pane active. Clicking a branch or a tag does the same with its pane. Clicking a commit selects it, opens its details and makes the commit pane active. Clicking a changed file selects it, opens its diff and makes the commit details pane active. Clicking the "Commit details" row selects it, opens the "Commit details" pane and makes the commit details pane active. Each close button closes its pane and makes the pane to its left active when the closed pane was active.
- Clicking anywhere in a pane, its title bar, an item, a button or its empty space, makes it the active pane, in every pane: the repo details pane, the commit pane, the commit details pane, the "Commit details" pane, the changes pane, the file pane and the tag pane. A click on an item or a button still does what it does, and where that sets the active pane itself, as a click on a commit or a close button does, that pane is the one left active. A click in the space between the panes leaves the active pane as it is.
- The repo explorer page takes the keyboard focus when it opens, so the keys work at once after the left sidebar's link or Ctrl+1 opened it.
- The arrow keys, Page Up, Page Down, Home, End, Enter, Escape, M and C are the repo explorer page's own keys, apart from Ziggy's shortcuts. The page handles them itself while it is shown and keeps them from the rest of the page, so an arrow key, Page Up or Page Down moves the selection and leaves the page's scroll as it is. It leaves them alone while a text box, link, button, menu or dialog has the focus or Ctrl, Alt or Cmd is held, and leaves M and C alone while Shift is held.
- Ctrl+C (Cmd+C on macOS) copies the selected item of the active pane to the clipboard: the selected commit's full hash in the commit pane, and the selected file's path from the root of the repo in the commit details pane and in the changes pane, in the Unstaged and the Staged lists. In the repo details pane, on the "Commit details" row, in the file pane and in a pane with no item selected, Ctrl+C leaves the clipboard holding what it held. The page handles the key on the document in the capture phase, as it does its other keys, so it runs before the Edit menu's Copy shortcut, which it keeps from running.
- Ctrl+C is left to the Edit menu's Copy, which copies the selected text as usual, while a text box, link, button, menu or dialog has the focus, such as the commit message box, and while the user has selected text on the page, such as part of a commit's description.
- Returning to the repo explorer is Graft's Repo Explorer action, a Ziggy action named `open-repo-explorer` with the shortcut `CmdOrCtrl+1`. Its handler opens the repo explorer page. Ziggy runs it from any page, also while a text box has the focus, because the shortcut holds Ctrl or Cmd.
